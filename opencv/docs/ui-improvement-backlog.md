## 높음

### 1. 사진 보관함 상단 필터 줄 정리

- **현상**: `폴더 가져오기 · 하위 폴더 포함 · 검색 · 앨범 · 태그 · 검토 · 정렬 · 새로고침`이 한 줄에, 그 아래 `이전 · 페이지 · 다음 · 앨범에 추가 · 태그 추가 · 태그 제거 · 자르기 화면에서 열기`가 또 한 줄에 놓여 있습니다. 기본 창 너비(1100px)에서 "하위 폴더 포함" 글자가 잘리고, 검색 입력란은 글자 두세 개 너비밖에 안 됩니다.
- **제안**:
  - 검색란을 넓게 한 줄로 두고, 앨범·태그·검토·정렬은 그 아래 필터 줄로 분리합니다.
  - 선택한 사진에 대한 동작(앨범에 추가, 태그 추가/제거, 열기)은 사진을 선택했을 때만 보이게 합니다.
  - 페이지 이동은 목록 아래로 내립니다.
- **위치**: `ui/widgets/management/library_page.py`, `ui/widgets/management/library/layout.py`

### 2. 폴더 감시 테스트 간헐적 멈춤

- **현상**: `_test_watch_readiness_is_owned_by_auto_processor`가 가끔 끝나지 않습니다. 세 번 실행 중 한 번꼴로 재현됐고, 멈춘 지점은 `core/file_watch/folder_watcher.py`의 `stop()`입니다 (`auto_processor.stop()` → `folder_watcher.stop()`, Windows의 `QFileSystemWatcher` 스레드가 살아 있는 상태).
- **영향**: 푸시 훅과 CI가 selftest를 돌리므로, 이때 걸리면 푸시가 끝나지 않습니다. 실제 앱에서 폴더 감시를 끌 때 같은 멈춤이 생길 가능성도 확인이 필요합니다.
- **제안**: `stop()`에서 감시 스레드를 기다리는 방식(잠금 순서, 대기 시간 제한)을 점검합니다. UI가 아니라 core 변경입니다.

### 3. 푸시 훅이 시스템 Python을 사용

- **현상**: `scripts/pre-push` → `scripts/verify.sh`가 PATH의 `python`과 `pyright`를 그대로 씁니다. 시스템 Python에 PySide6·OpenCV가 없으면 selftest 95건이 import 오류로 실패해 푸시가 막힙니다.
- **임시 방법**: `opencv/.venv/Scripts`를 PATH 맨 앞에 두고 푸시합니다.
- **제안**: verify 스크립트가 `opencv/.venv`가 있으면 그 인터프리터를 먼저 쓰도록 합니다 (`verify.sh`, `verify.ps1` 둘 다).

## 중간

### 4. 관리 화면의 빈 상태 안내

- **현상**: 사진 보관함·확인 필요·중복 사진·작업 기록·앨범은 데이터가 없으면 빈 표만 보입니다. 처음 쓰는 사람은 무엇을 해야 내용이 생기는지 알 수 없습니다.
- **제안**: 화면마다 한두 줄짜리 안내를 넣습니다. 예: 사진 보관함 — "아직 사진이 없습니다. 사진을 자르면 여기에 모입니다."
- **참고**: `DESKTOP_UI_DESIGN_RULES.md` 14절(빈 테이블), 17절(페이지 상태)
- **위치**: `ui/widgets/management/*_page.py`. 공통 컴포넌트로 만들어 `ui/components.py`에 두는 것이 좋습니다.

### 5. 단순 알림을 막는 대화상자 줄이기

- **현상**: "자를 사진이 없습니다", "이미 자르는 중입니다", "사진 폴더를 먼저 선택해 주세요" 같은 안내가 확인 버튼을 눌러야 닫히는 대화상자로 뜹니다.
- **제안**: 선택이 필요 없는 안내는 상단 알림(InfoBar, `ToastManager`)과 상태 표시줄로 바꿉니다. 종료 확인, 삭제 확인, 고친 영역 사용 여부처럼 선택이 필요한 것만 대화상자로 남깁니다.
- **위치**: `ui/main/actions/batch.py`의 `QMessageBox.warning` / `information` 호출들, `ui/main/actions/tools.py`의 중복 사진 찾기 결과

### 6. 스캔 종류 선택이 기억되지 않음

- **현상**: 자르기 화면의 `스캔 종류`는 고르는 순간 영역 찾기 설정값을 바꿔 주지만, 무엇을 골랐는지는 저장하지 않습니다. 프로그램을 다시 켜면 항상 "현재 설정 그대로"로 표시됩니다. 설정값 자체는 유지되므로 결과에는 영향이 없고 표시만 어긋납니다.
- **제안**: 고른 스캔 종류 id를 설정에 저장하고, 영역 찾기 탭에서 값을 직접 바꾸면 "현재 설정 그대로"로 되돌립니다. 설정 저장 형식에 필드가 하나 추가됩니다.

### 7. "미리보기 회전"이 결과에 반영되지 않음

- **현상**: 도구 메뉴의 `미리보기 회전`(Ctrl+R)은 화면의 원본만 90° 돌립니다. 영역을 다시 찾지 않고, 저장되는 결과도 바뀌지 않습니다. 오해를 줄이려고 이번에 자르기 화면 버튼에서는 뺐고 메뉴에만 남겼습니다.
- **제안**: 둘 중 하나로 정합니다.
  - 회전을 사진별 설정으로 저장해 실제 결과에 반영한다.
  - 기능을 없앤다.

### 8. 저장한 설정과 작업 프로필의 중복

- **현상**: 설정 묶음을 다루는 입구가 세 군데입니다.
  - 자르기 화면의 `저장한 설정` 목록
  - 메뉴의 `저장한 설정` 화면 (저장·삭제·내보내기·가져오기)
  - 도구 메뉴의 `작업 프로필 > 프로필 불러오기...`
- 프로필 관리자(`core/batch_profile_manager.py`)는 내부적으로 같은 저장소(recipe manager)를 읽으므로 사용자에게는 같은 목록이 이름만 다르게 두 번 보입니다.
- **제안**: `작업 프로필` 메뉴를 없애고 `저장한 설정`으로 합칩니다. 프로필에만 있는 분류 규칙(category rules)을 어디서 편집할지 먼저 정해야 합니다.

## 낮음

### 9. 보조 창의 고정 색상

- **현상**: 아래 창들은 어두운 테마용 색상이 코드에 고정돼 있어 밝은 테마에서 어울리지 않습니다. 이번에 손댄 자르기 화면·설정 패널·히스토그램은 해당하지 않습니다.
  - 진행 창: `ui/widgets/progress_dialog.py`
  - 여러 사진 비교 창: `ui/widgets/multi_compare_window.py`
  - 썸네일 목록: `ui/widgets/thumbnail_grid_widget.py`
  - 크게 보기: `ui/widgets/fullscreen_viewer.py` (사진 뷰어라 항상 어두운 것이 의도일 수 있음)
- **제안**: `ui/design_tokens.py`의 토큰과 팔레트 색으로 바꿉니다. `ui/components.py`의 `make_secondary()`를 쓰면 보조 글자색은 스타일시트 없이 처리됩니다.
- **함께 볼 것**: `ui/styles/themes.py`(약 700줄)는 Fluent 위젯이 없을 때만 쓰는 예비 스타일시트입니다. 배포본은 Fluent를 항상 포함하므로 유지할지 결정이 필요합니다. 지우려면 `tests/test_ui_fluent.py`의 `test_legacy_theme_fallback_still_available`도 함께 정리해야 합니다.

### 10. 남은 이모지 아이콘

- **현상**: 화면에 보이는 문구는 번역 카탈로그 값으로 바뀌어 이모지가 없지만, 소스에는 남아 있습니다.
  - 설정 탭 소스의 한국어 원문(`"✨ 후처리 옵션"`, `"📷 기본"` 등)과 이를 키에 연결하는 `ui/widgets/settings/i18n_bindings.py`
  - 예비 토스트(`ui/widgets/toast_notification.py`의 `TOAST_TYPES`) — Fluent가 없을 때만 보임
- **제안**: 설정 탭 문구를 원문 매칭이 아니라 `t("키")` 직접 호출로 바꾸면 이모지와 바인딩 표를 함께 없앨 수 있습니다. `_test_settings_i18n_literal_binding_coverage`가 이 구조를 검사하므로 같이 고쳐야 합니다.

### 11. 창 크기를 바꿔도 미리보기가 다시 맞춰지지 않음

- **현상**: 사진을 처음 띄울 때는 화면에 맞추지만, 그 뒤 창 크기를 바꾸거나 가운데 구분선을 끌면 크기가 그대로입니다. `화면에 맞춤`을 눌러야 합니다.
- **제안**: 사용자가 직접 확대·축소하지 않은 상태라면 크기 변경 시 자동으로 다시 맞춥니다.
- **위치**: `ui/widgets/preview_panel.py`, `ui/widgets/zoomable_view.py`

### 12. 일본어·중국어·스페인어 번역 부족

- **현상**: 영어는 776개 키 전부, 한국어는 형식 문자열 2개를 뺀 전부가 채워져 있지만 `ja.py` / `zh.py` / `es.py`는 각각 80여 개뿐이라 나머지는 영어로 표시됩니다.
- **제안**: 자르기 화면과 진행 창에 나오는 문구(`central.*`, `preview.*`, `batch.*`, `progress.*`, `scene.*`)부터 채웁니다.

### 13. 문서·코드 잔여 정리

- `README.md` 단축키 표의 "마우스 우클릭 드래그로 이동"은 실제 동작과 다릅니다. 실제로는 Ctrl+드래그 또는 휠 버튼 드래그입니다 (`zoomable_view.py`). `Space`(자르기 시작), `←` `→`(사진 넘기기), `Enter`(영역 다시 찾기)도 표에 없습니다. `README_EN.md`의 `Right Click + Drag`도 같은 오류입니다.
- `README.md` / `README_EN.md`의 설정 패널 탭 설명은 탭 이름만 새로 바꿨고, 각 탭의 항목 설명은 예전 용어(Canny, CLAHE 등) 그대로입니다.
- `opencv/README_v8.md`는 v8 기준 문서라 "툴바에서 프리셋 선택", "변환 시작" 같은 예전 화면 설명이 남아 있습니다.
- `ui/main/window.py`의 `MainWindow.TITLE` 상수는 쓰이지 않습니다 (창 제목은 번역 키 `app.title`로 설정).
- `opencv/photo_cropper_onefile.spec`에는 `photo_cropper.ui.components`가 명시돼 있지 않습니다. 빌드와 실행은 정상이었지만 `photo_cropper.spec`(onedir)과 맞춰 두는 편이 안전합니다.
- `DESKTOP_UI_DESIGN_RULES.md`는 `ui/design_tokens.py`, `ui/components.py`, `ui/fluent.py`의 주석에서 참조하지만 저장소에 올라가 있지 않습니다. 올릴지 결정이 필요합니다.
