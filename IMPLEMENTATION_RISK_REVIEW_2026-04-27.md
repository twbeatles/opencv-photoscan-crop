# Implementation Risk Review - 2026-04-27

## Status

All proposed Management/Library stabilization items from this review have been implemented and integrated into the project documentation.

## Completed Changes

- Added shared file-list preflight for Management rerun/reprocess, Batch, and Watch-style execution through `BatchRuntimeFlow.resolve_file_batch_paths(...)`.
- Moved Library import, exact duplicate rebuild, near duplicate rebuild, and search-index rebuild into maintenance/background job flows.
- Hardened SQLite connections with `foreign_keys=ON`, `busy_timeout=5000`, best-effort WAL initialization, and store-level write locking.
- Added non-destructive invalid-source handling in `LibraryRepository.upsert_source()` for empty, missing, directory, unsupported, and unreadable image inputs.
- Added FTS dirty-state tracking and `maintenance_search_index` rebuild support.
- Reworked asset timeline lookup to avoid broad review-window scans.
- Added near-duplicate rebuild scan-scope summary fields.
- Added job-summary observability for thumbnail, AI, OCR, and person-provider failures.
- Added repository mixin typing contracts in `core/library/_repository_protocol.py`.
- Removed broad file-level pyright attribute-access suppressions from the touched library, batch, and image implementation areas.
- Updated PyInstaller specs to explicitly include `photo_cropper.core.library._repository_protocol` while preserving `collect_submodules(...)` coverage.
- Updated README/README_EN and `;opencv/CLAUDE.md` so the deleted refactor-status documents are superseded by integrated documentation.
- Expanded `.gitignore` for SQLite sidecar files generated by WAL/journal modes.


## Notes

- WAL remains best-effort because some deployment or filesystem environments can reject the mode; failure is intentionally not fatal.
- Management jobs use background execution, button disabling, toast completion, and current-page refresh as the v1 completion standard.
- `invalid_source` is intentionally a return state rather than an exception so existing ingest/relink callers remain compatible.
